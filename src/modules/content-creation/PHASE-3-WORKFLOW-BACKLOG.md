## Prioritization Framework

Use this framework to assess which workflows to build first:

### Priority Scoring Criteria

1. **User Demand (1-5):** How often will users need this workflow?
2. **Value Impact (1-5):** How much value does this add to the module?
3. **Dependencies (1-5):** How many other workflows depend on this? (5 = many dependencies)
4. **Complexity (-1 to -5):** Implementation difficulty (negative score)
5. **Existing Alternatives (-1 to -3):** Can users achieve this another way? (negative if yes)

**Priority Score = User Demand + Value Impact + Dependencies + Complexity + Existing Alternatives**

### Priority Tiers

- **Critical (Score 10+):** Build in next sprint
- **High (Score 7-9):** Build in next 1-2 months
- **Medium (Score 4-6):** Build when capacity allows
- **Low (Score <4):** Defer to Phase 4 or future enhancement
