# Story 1.6: Project Lifecycle and Archive Management

## Status

Development

## Story

**As a** research journalist,  
**I want** to archive completed projects and manage project lifecycle states with comprehensive archive/restore capabilities,  
**so that** I can maintain an organized workspace while preserving completed research for future reference and maintaining project accessibility across different lifecycle phases.

## Acceptance Criteria

1. `project-archive` task moves completed projects to archive location while maintaining full accessibility and preserving all analysis outputs
2. `project-restore` task brings archived projects back to active workspace with complete functionality restoration
3. Project status progression (active → review → completed → archived) is tracked and manageable through enhanced status management
4. Archived projects remain searchable and discoverable but don't clutter active project listings or daily workflows
5. Archive operations preserve all analysis outputs, source materials, relationships, and cross-project references established in Stories 1.1-1.5

### Archive System Architecture

**Archive Directory Structure** [Extension of Story 1.1 patterns]:

- `archive/{year}/{project-name}/` - Organized by archive date for temporal organization
- Preserve complete project structure: `{references,analyses,drafts,config}` directories
- Add archive metadata: `archive-info.json` with archive date, reason, and restoration information
- Maintain search indexing: `archive-index.json` for efficient search and discovery

**Archive Metadata Model** [New for Story 1.6]:

- `archive_date`: timestamp - When project was archived
- `archive_reason`: string - Human-readable reason for archival
- `original_location`: string - Original active project path for restoration
- `archive_status`: enum - Archive health status (healthy, degraded, corrupted)
- `restoration_count`: number - Number of times project has been restored
- `last_accessed`: timestamp - Last archive search or access time
- `preserve_relationships`: boolean - Whether cross-project relationships should be maintained

**Project Lifecycle Model** [Extension of existing project metadata]:

- `status`: enum - Extended to include "active", "review", "completed", "archived"
- `lifecycle_history`: array - Timeline of status changes with timestamps and reasons
- `archive_eligible`: boolean - Whether project can be archived based on business rules
- `restore_path`: string - Path for restoration when project is archived
- `lifecycle_locked`: boolean - Whether status changes are restricted
