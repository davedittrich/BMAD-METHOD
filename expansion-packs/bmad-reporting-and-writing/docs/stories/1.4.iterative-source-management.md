# Story 1.4: Iterative Source Management

## Status
Review

## Story
**As a** research journalist,  
**I want** to incrementally add research materials to projects with intelligent deduplication, versioning, and cross-project referencing capabilities,  
**so that** I can build comprehensive research databases iteratively while maintaining organization and avoiding duplicate work.

## Acceptance Criteria
1. `project-add-source` task enables incremental addition of research materials with automatic content type detection
2. Intelligent deduplication prevents duplicate sources across projects with cross-referencing capabilities
3. Source versioning and change tracking maintains comprehensive research material history
4. Source organization through tagging and categorization enables efficient material discovery
5. `project-search` task provides cross-project source discovery with advanced filtering
6. `project-archive` task enables proper lifecycle management for completed research materials
7. Seamless integration with Stories 1.1, 1.2, and 1.3 infrastructure without disrupting existing functionality

### Data Models

**Source Reference Model** [Source: architecture.md#data-models-and-schema-changes]
- `url`: string - Source URL for YouTube videos or document references
- `type`: enum - Content classification (video, document, transcript, external-source)
- `added_date`: timestamp - When source was added to project
- `analysis_status`: enum - Processing state (pending, analyzing, completed, archived)
- `output_files`: array - Generated analysis and transcript file references
- `tags`: array - User-defined categorization labels for organization

**Enhanced Source Reference Model** [Extension for Story 1.4]:
- `version`: number - Source version for change tracking and history
- `last_modified`: timestamp - Most recent update to source or metadata
- `fingerprint`: string - Content fingerprint for deduplication detection
- `cross_references`: array - Links to same source in other projects
- `source_history`: array - Change log with timestamps and modification details
- `collection_membership`: array - Source collections or groups for organization
- `auto_tags`: array - System-generated tags based on content analysis
- `archive_status`: enum - Lifecycle state (active, archived, deleted)

**Deduplication Reference Model** [New for Story 1.4]:
- `canonical_url`: string - Normalized URL for duplicate detection
- `content_hash`: string - Content-based fingerprint for material comparison
- `duplicate_sources`: array - List of equivalent sources across all projects
- `primary_project`: string - Project containing the primary/master copy
- `reference_projects`: array - Projects referencing this source with cross-reference metadata

**Source Collection Model** [New for Story 1.4]:
- `collection_id`: string - Unique identifier for source grouping
- `name`: string - Human-readable collection name
- `description`: string - Collection purpose and scope
- `created_date`: timestamp - Collection creation date
- `source_ids`: array - List of sources included in collection
- `collection_tags`: array - Tags applied to entire collection
- `access_level`: enum - Collection visibility (project-only, cross-project, public)
